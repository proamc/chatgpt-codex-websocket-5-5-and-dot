# Clash + ChatGPT / Codex + dot：新 Mac 配置指南

**系统代理开启、TUN 关闭；给 ChatGPT 做一个无终端的专用启动入口，再按需要把 Codex 模型请求改为 HTTPS。**

本仓库只有两份指令文档。阅读本页了解做法；需要本地助手帮你配置时，把 [forchatgpt.md](forchatgpt.md) 发给新电脑上的 ChatGPT/Codex，并说明“请按这份指南检查并配置这台 Mac”。助手会根据你的实际安装位置和端口制作入口，不需要下载别人编译的应用。

## 我为什么这样设置

我原本以为，Clash 的系统代理开了，所有软件就会跟着它上网。后来遇到的情况却是：浏览器能访问网页，ChatGPT/Codex 仍然反复提示 `request timed out`，dot 也可能无法连接本机。

我试着打开 TUN，其他软件又出现了网络或登录异常。于是我保留已经能用的系统代理，给 ChatGPT 做一个专用入口：打开时把 Clash 地址直接交给它，它启动的本机执行器也能继承这些代理变量。日常只需先开 Clash，再点程序坞的图标，不再弹终端。

模型传输则单独处理：在出现模型 WebSocket 超时的这套环境里，我为新的 Codex 聊天配置了 HTTPS，并做了实际请求验证。dot 恢复后，也通过连接的 Mac 完成了一次真实的只读系统查询。

## 先分清楚这两个改变

| 对象 | 采用的办法 | 解决方向 |
| --- | --- | --- |
| Codex 模型请求 | 为提供商关闭 Responses WebSocket 支持，验证 HTTPS 传输 | 处理当前网络中的模型 WebSocket 超时与反复重连 |
| dot 本机连接 | 让桌面应用及本机执行器获得显式代理 | 处理部分网络客户端没有采用系统代理、无法连上云端中继的问题 |

**dot 仍可能使用 WebSocket / WSS。这个方案不能把 dot 强制改成 HTTPS。** 修改模型配置和让 dot 获得代理，是两件独立的事；网络节点不稳定时，HTTPS 也可能超时。

## 在新 Mac 上按顺序做

### 1. 准备基础环境

安装官方的 Clash Verge Rev 和 ChatGPT/Codex 桌面应用，导入自己的 Clash 订阅，登录自己的账号。先确认浏览器能正常访问需要的服务。

| Clash 设置 | 使用值 |
| --- | --- |
| 模式 | 规则模式，检查实际连接命中的规则与节点 |
| 系统代理 | 开启 |
| TUN / 虚拟网卡 | 关闭 |
| HTTP / Mixed 混合端口 | 以本机设置为准，常见为 7897 |
| 允许局域网 | 仅本机使用时可以关闭 |

先保持这套基线，不同时调整 TUN、DNS、路由或其他 VPN。没有可用节点时，先解决节点问题。

### 2. 让本地助手制作专用入口

把 [forchatgpt.md](forchatgpt.md) 交给拥有这台 Mac 本地操作能力的助手，请它检查端口、应用路径，再制作一个 `.app` 启动入口并固定到程序坞。

入口只向这次启动的原版应用及其子进程传入代理变量，不修改原版安装包，也不把代理写入整个账号的登录环境。正常打开时没有终端窗口；应用已经运行但未采用这些参数时，提示先保存任务并完整退出，不强行关闭。

制作完成后，保存正在进行的任务，用 `Command + Q` 完整退出原版应用，再从专用图标启动。已经运行的程序不会因新入口被创建，就自动换上代理参数。

### 3. 配置新的 Codex 聊天使用 HTTPS

完整退出应用，备份 `~/.codex/config.toml`。保留模型和其他设置，把下面这行放在第一个 `[表名]` 之前；已有同名键时替换，不能重复添加：

```toml
model_provider = "openai_https"
```

在文件末尾添加下表；同名表已存在时更新它：

```toml
[model_providers.openai_https]
name = "OpenAI HTTPS"
requires_openai_auth = true
wire_api = "responses"
supports_websockets = false
```

不填写第三方 `base_url`，保持自己的 OpenAI 登录方式。内置 `openai` 提供商 ID 是保留项，不要尝试用同名表覆盖。

从专用入口重启后，**新建一个本地 Codex 聊天**。旧聊天可能保留创建时的提供商，必须核对新聊天的实际传输，不能只看文件里写了什么。

### 4. 连接 dot，验证真实本机操作

在新 Mac 的 ChatGPT 中打开 dot 的资料页，在电脑列表中允许访问这台 Mac。保持电脑联网、应用打开。当前官方说明每个 dot 只能同时连接一台个人电脑，迁移时确认选中的是新电脑。

给 dot 这条指令：

> 请在我刚连接的这台 Mac 上查询 macOS 版本和构建号，并查询 uname -s。报告实际工具执行结果。只做只读查询，不读写我的个人文件，不使用云端电脑代替。

## 用这张表验收

| 项目 | 通过标准 | 状态 / 时间 |
| --- | --- | --- |
| 入口 | 点图标能打开原版应用，无终端窗口 | 未测 |
| 模型对话 | 新本地聊天连续 6 次短请求均完整回复 | 未测 |
| 模型传输 | 只读核对新聊天提供商与日志，确认 `openai_https`、`responses_http`，记录是否重试 | 未测 |
| dot 首次 | 实际在这台 Mac 查询系统版本，取得工具结果 | 未测 |
| dot 约 1 分钟后 | 再做同样的本机查询 | 未测 |
| dot 约 5 分钟后 | 再查一次，记录断连或重连 | 未测 |
| Mac 重启后 | 等 Clash 启动，再点专用入口，重新验证模型与本机操作 | 未测 |

网页能打开、端口在监听、电脑显示在线，分别只能证明一层。不能用它们代替本机执行成功。

## 遇到问题时

- 网页也打不开：先查 Clash 节点、订阅与分流。
- 入口提示已运行：保存任务，完整退出原版应用，再从专用入口打开。
- 模型仍重连：核对新聊天、实际传输、提供商和节点；不能假定所有超时都由 WebSocket 引起。
- 模型能聊但 dot 失败：查本机授权、执行器代理与 WSS 中继连接，单独验证。
- 开 TUN 后其他软件断网：先恢复系统代理开、TUN 关；TUN 路由和 DNS 兼容需要另外排查。

这套入口不是 TUN，也不会自动接管 Telegram 等其他独立软件。其他软件仍按各自支持情况使用系统代理或内部代理。

## 如何撤销

保存任务并完整退出应用，再从原版图标打开，就不再通过专用入口注入代理变量。删除专用入口及其程序坞项目即可。

模型 HTTPS 是独立配置。需要撤销时退出应用，恢复自己的配置备份；如果之后还有其他配置变更，只还原本次字段，保留后续更改。
